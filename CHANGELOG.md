# Changelog

## [Unreleased]

### Added

- **Conversation titles:** Derive a short title locally from the first accepted user message, with labels for attachment-only turns. Add inline sidebar rename with keyboard save/cancel, focus restoration, and retained input on save failure. Return the canonical saved title from the server; reject empty or overlong normalized titles and protect confirmed renames from stale list responses.
- **Model selection:** Share a model picker between Settings and the composer. Offer distinct Vortex Auto, OpenRouter Auto, and concrete model choices, searchable and sortable All models, and manual model ID entry. Settings saves the default for new chats; composer pins affect future turns in that conversation. Add `GET/PATCH /api/conversations/{id}/model`.
- **Vortex Auto:** Pick the lowest estimated-cost eligible model from a fresh catalog using known input/output rates, relevant fees, modality and tool support, and estimated context headroom. Account for prompt, tools, history and attachments; resolve once per turn and pass the resolved model to delegates. Refuse stale or incompatible routing without silently falling back or consuming the draft. This is separate from the Recommended list and the provider's own Auto alias.
- **Budget shortlist and catalog:** Use OpenRouter's weekly usage order when available and a reviewed exact-ID mapping for open weights and licensing. Recommended defaults to five entries and USD 1 input / USD 3 output per million tokens, with editable session-only bounds and list size. Exclude unknown prices, ineligible licenses, retired entries, routers, and batch endpoints from the shortlist without hiding them from All models. Show pricing, fees, capabilities, context, advertised output maximum, license/weights links, restrictions and retirement details when known. Label rankings as popularity, not quality; label last-known-good data as stale and keep a manual-ID path when the catalog is unavailable.
- **Usage and provenance:** Record the assistant reply's run ID, requested provider model, and provider-reported serving model when available. Show live requested-model and saved provenance labels. Add `GET /api/conversations/{id}/usage` and a per-chat reported token badge for input, output and total; reconcile cumulative counters once per run across coordinator runs, retries, and delegates, with missing or incomplete data shown explicitly.
- **Reply diagnostics and continuation:** Persist the normalized provider finish reason, requested output allowance, and final call's reported completion tokens when available. Distinguish normal stops, limit stops, provider errors, filtering and unknown reasons. Offer Continue on eligible replies as a new turn without consuming the existing draft or staged files.

### Changed

- **Generation limits:** Fresh settings default to Vortex Auto and request up to 16,384 output tokens, up from 4,096. Preserve explicit saved settings. Distinguish the configured ceiling (at most 100,000), advertised completion limit, estimated context headroom, run token budget, and actual reply usage. Offer an explicit adjustment when the configured ceiling exceeds the advertised limit; it is not a guaranteed reply length. Bound each request's output by the remaining per-run budget and stop at exhaustion. Instruct the coordinator to attempt the requested scope of long lists when feasible without bypassing safeguards.
- **Provider and retry behavior:** Preserve returned partial text on a verified output-limit stop and surface actionable status; do not treat context rejection, inline provider errors, or missing finish reasons as normal stops. Remove automatic provider completion retries while retaining explicit Retry for eligible failures. Send and Retry use the effective conversation model, and return errors if conversation or history retrieval fails instead of proceeding without context.
- **Composer and reconnect:** Keep each chat's unsent text and attachment chips in memory while switching conversations or Settings; clear accepted content only after a successful send and keep failed submissions editable. Prevent overlapping sends while a turn or model save is in progress, and do not treat IME composition as submission. Restore the latest coordinator run rather than a delegate on reopen, reattach active streams, guard against stale events and snapshots, and reload saved messages and usage after completion or reconnect.
- **Storage and compatibility:** Add SQLite fields for title origin, model preference, reply provenance/summary and incomplete usage. Backfill eligible legacy placeholder titles from the first user turn without reordering chats or overwriting manual titles. Legacy model preferences remain inherited until set; old reply metadata is not guessed. Expand catalog, conversation, message, and usage API data without inventing values for older rows. Use the existing workspace `chrono` dependency in `vortex-llm` for catalog retirement-date handling and update `Cargo.lock`.
